# Current provider workspace

**Current matches** is an independent, read-only view over the locally validated football-data and PandaScore publications. It does not reuse the synthetic showcase or retrospectively imported CC0 research package. The default public profile shows **Live connection unavailable** and makes no live API requests or fixture fetches. The separately enabled processed publication profile is described below.

## Match research

Provider controls switch between Football / football-data and VALORANT / PandaScore. The initial Running filter reports the provider's accepted scope, including an explicit empty state when no active match is reported. Scheduled, Finished and All statuses remain actionable. Literal team/competition search and 25-record pagination apply through the bounded local API. UTC kickoffs group the current page; provider names and stable team IDs remain distinct from CC0 source identities.

`live_provider`, `live_status`, `live_search`, `live_page` and `live_match` preserve navigation through reload and browser history. The native match dialog supports Escape, focus return and a copyable URL. It shows match/team/event IDs, units, current revision, match observation, completion evidence and publication version/fingerprint. Football uses goals; VALORANT uses series maps and the supplied best-of value. Scheduled, cancelled and postponed records display dashes, even when upstream default score fields contain 0–0. Those original fields remain labelled in provenance and do not establish a played result.

No official standings, player roster, round feed, map-by-map history, completeness claim or model forecast is added. Unsupported source records remain excluded from the canonical match board; their count is visible in collection evidence. A separate announcement calendar is outside this milestone.

## Freshness and failure behavior

The compact collection panel shows status, last successful provider poll and dataset observation cutoff. Its disclosure keeps last publication change, declared poll scope, retained coverage, provider interval, latest check's counts, request budget and error categories visible on demand. An absent legacy scope explicitly remains unknown. A recent successful poll can retain exactly the same publication and observations.

The browser checks local health and matches after each bounded eight-second refresh interval. Provider identity, dataset version, fingerprint and cutoff must agree before a page is accepted. At most 25 rows are rendered. Query/provider changes cancel pending requests, and leaving the view stops polling. The browser reads the backend registry, without making direct provider calls or consuming provider credentials.

Failed checks preserve only the last validated page for the same provider and filters, with an explicit stale/last-verified warning. Different-version responses are rejected and retried by the next check. Invalid new publications never replace existing verified data. A server-retained last-good publication remains labelled as such. Unconfigured workers, pending credentials, quota exhaustion, unavailable transport and genuinely empty filters have explicit states. Detail requests use the same publication guard and retain matching validated evidence after a transient detail error.

Football's free-tier score delay is always disclosed. PandaScore is labelled match-level series data, without asserting instant rounds or unreported latency. The visible football attribution reads **Football data provided by the Football-Data.org API**; the VALORANT attribution reads **Source: PandaScore**. Both link to the corresponding provider. Provider API accounts and permitted access remain required by the local collection workflow; this document contains no credentials.

## Match-scoped questions

The selected current-match dialog includes **Ask about this match**. Evidence is the explicit default; Local AI is a separate radio choice. Suggestions fill the question without making an inference request. Evidence returns deterministic structured records, while Local AI requests source-grounded interpretation through `/live/chat`. The browser submits the selected provider and stable match ID; it never calls a provider or redirects the question to synthetic or CC0 research chat.

CPU generation can take several minutes. A busy state exposes **Cancel current question**, and the browser stops waiting after 200 seconds, beyond the server's 180-second budget. Browser cancellation also prevents a late response from replacing a subsequent answer; it does not promise to stop server-side computation. Closing the dialog or changing its provider/match aborts pending question and feedback requests. A failed request exposes **Retry selected mode**. Model-busy, unavailable and deadline failures do not trigger an implicit switch to Evidence.

Every answer labels its captured provider, dataset and observation cutoff. Citations and tool records must agree with that answer's full fingerprint, source and version. A captured publication may legitimately differ from the independently refreshing board and receives an explicit notice. Provider health is labelled **at capture**, without presenting an inference-old poll as a new check. Source references and structured records expand on demand, alongside trace, model metadata, latency and the six-tool ceiling. Scheduled score fields remain explicitly unconfirmed in the tool evidence.

Feedback submits the answer's original provider, trace and fingerprint with an optional comment. It is stored through the separate current-data feedback route. The public site exposes no current-match AI or feedback action, makes no current-data API request and substitutes no stored package. Reference validation establishes provenance; semantic model quality requires the separate native-model evidence described in [Current-data investigations](live-agent.md).

Controlled browser verification uses original test-only transport responses, including an older accepted capture, a deliberately inconsistent citation, provider navigation during a held request, model-busy/unavailable responses, cancellation and a simulated 200-second deadline. These checks measure frontend behavior rather than native generation or provider accuracy. The initial cancellation diagnostic and the focused correction remain preserved separately under ignored `data/live-chat-diagnostic-01/` and `data/live-chat-cancel-fix/`.

The corrected combined board/question regression passed 11 applicable cases in 90.834 seconds with zero retries and 16 intentional project-scope skips. After the final mobile trace layout and additional tool-fingerprint guard checks, the question suite passed six applicable cases in 30.4 seconds, with zero retries and nine intentional scope skips. These results are preserved in `data/live-chat-qa-02/` and `data/live-chat-qa-03/` respectively; the latter records frozen-source hashes.

## Optional published fixtures and results

The public profile requires both `VITE_STATIC_DEMO=true` and `VITE_PUBLISHED_CURRENT_DATA=true`. Its **Current matches** board reads only this website's `current/manifest.json`, `football-data.json` and `pandascore.json`. It exposes fixtures and recent results from the rolling UTC window, source check times, football's score delay and VALORANT's match-level series coverage. The visible window count includes any clipping. A recent source check remains distinct from the data observation cutoff. The profile has no public AI action, direct provider API connection, original canonical match context or unlicensed logos.

The processed contract is [arena-live-display-1.0](live-publication.md). A manifest is limited to 64 KiB, each provider file to 2 MiB and each provider to 500 cards. Before rendering, the client checks the exact file inventory, UTF-8 bytes, duplicate JSON keys, SHA-256 checksums, derived logical identities, provider attribution, source clocks, coverage counts, window bounds, card ordering and result semantics. Original provider IDs and records are not reconstructed from derived display IDs. Scheduled, cancelled and postponed cards never show a played score; running scores are provisional and finished VALORANT results must satisfy the supplied series format.

The browser checks the manifest after a bounded 60-second interval. Full canonical equality with an already verified manifest reuses its accepted package without downloading provider bodies again. Equality includes the file checksums, fingerprint, versions and generation time; a matching short display identity alone is insufficient. A changed manifest requires both verified bodies and a second manifest read, so a deployment race cannot mix publications. A failed, oversized, tampered, malformed or mismatched publication retains only previously verified cards with an explicit warning. A subsequent unchanged valid manifest clears the client error. Source age continues to advance from `last_success_at`; a new build cannot renew an old successful source check.

Provider, status, literal team/competition search, page and selected display match reuse the `live_*` URL fields. Filtering precedes 25-card pagination. A native match dialog exposes copyable navigation, Escape and focus return. Progressive source details contain the processed card, declared source scope, coverage, canonical provenance and display identity. Required source credits and the provider-derived license notice remain visible below the board. These cards are subject to provider terms, separately from MIT code and CC0 research records.

The normal browser configuration includes independent `published-desktop` and `published-mobile` projects on an isolated subpath preview. Their original TEST ONLY responses are self-contained; no published fixture, private provider table or actual source asset is altered. Journeys cover filters, paging, Unicode names, selected-match reload, keyboard dismissal, source-age advancement, unchanged-manifest body reuse, failure recovery, resealed invalid fields, cross-provider data, deployment races and an oversized first manifest. Default static projects explicitly disable the publication flag and retain their unavailable/no-API behavior. The earlier simulated-clock deadline diagnostic is preserved in ignored `data/published-current-diagnostic-01/`; it is not counted as a passing run.

After the final copy, mobile spacing and manifest-reuse changes, all ten applicable publication-profile browser executions passed in 26.3 seconds with zero retries. TypeScript/Vite, formatting and diff checks passed. Results, screenshots and source hashes are preserved under ignored `data/published-current-final-05/`. This focused result is separate from the broader integration and release gates.
